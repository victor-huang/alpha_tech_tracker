### Entry ΔFillIntr > $0.20 — Root Cause Analysis

#### FN C630 [M1] — ΔFillIntr = +$3.49

Full escalation sequence:
```
step0.5  fair=73.00  bid=69.3 ask=73.0 intrinsic=72.67 (stale)  spread=5.2%  → FILLED at 10:17:22
```

**Root cause — stale signal stock price, fair_price anchored to stale intrinsic (Bug #2 entry):**
The engine called `get_fair_price(stock_price=702.67)` (signal bar close at 10:10). By fill time (10:17:22), the stock had fallen to $699.51 — actual intrinsic = $69.51. The stale_bid path computed `fair = intrinsic + median_time_value = 72.67 + 0.33 = 73.00`, which was clamped to the ask at $73.00. If the engine had used the live stock price ($699.51) instead, fair would have been `69.51 + 0.33 = $69.84` — step0.5 would have placed a limit at $69.84 rather than $73.00, and escalated from there. Even at step1 mid = (69.3+73.0)/2 = $71.15, that would save $1.85 vs the $73.00 fill.

Stock movement during lag: −$3.16 (702.67 → 699.51). This was a 7-minute catch-up delay (engine restart + IEX buffer + deadline wait).

## TODO

### Fetch live stock quote at fair_price computation time

**Problem:** `get_fair_price()` computes intrinsic value using the stock price from the signal bar (e.g. FN $702.67 at 10:10 bar close). By the time the order is actually placed — after buffering, deadline wait, ranking, and contract selection — the stock price can be meaningfully different. In the FN C630 case, the stock had already dropped ~$3.55 in the 2+ minutes between signal bar close and order placement, causing the option to be priced $3.88 above fill-time intrinsic.

**Fix:** At the point `get_fair_price()` is called inside `_enter_option_position()`, fetch a fresh stock quote and use that price as the intrinsic floor instead of (or in addition to) the signal bar close. The bid/ask quote from the broker already captures the current market, but the intrinsic floor anchors to a stale stock price — updating it to the live stock price would tighten the limit and avoid overpaying when the stock moves between signal and order.

**Where to change — entries:** `trade_engine.py` → `_enter_option_position()`: instead of passing `signal.stock_price` (the signal bar close), fetch `_stock_bid_ask(ticker)` at the moment of order placement and use the mid as the live stock price.

**Where to change — exits:** `position_monitor.py` → exit path before calling `get_fair_price()`: same fix. On 2026-04-17, MSTR P180 exited at $14.75 (step0.5) when actual intrinsic was $15.47 — the engine passed the cached bar price ($165.24) instead of the live stock price ($164.53), computing a put intrinsic of $14.76 instead of $15.47 and costing $0.72/contract.

### Clamp step2 exit price to intrinsic floor before placing the order

**Problem:** The FILL_ESC exit ladder steps down in price: step0.5 (fair) → step1 (mid) → step2 (mid − spread/4) → step3 (max(bid, intrinsic)). For wide-spread options, step2 can drop below the current intrinsic value — and if it fills there, step3's intrinsic floor is never reached.

On 2026-04-17, APP P520 exited at **$39.90** (step2), while 1-min verified intrinsic was **$42.20** (15:50 bar close $477.795, put strike $520) — a **$2.30 loss below exercise value**. The spread was $7.10 (17%), so `mid − spread/4 = 41.65 − 1.78 = $39.88`, which is $2.32 below intrinsic. The stock was stable at $477–478 throughout — this was not a fast market move, purely a pricing ladder bug.

**Fix:** In `order_executor.py` at the step2 computation (~line 153), after computing `step2_price`, clamp it so a sell never goes below intrinsic:

```python
# after: step2_price = (mid + quarter_spread) if is_buy else (mid - quarter_spread)
if not is_buy and intrinsic is not None:
    step2_price = max(step2_price, intrinsic)
```

This requires making intrinsic available at step2. The cleanest approach: hoist the intrinsic computation (currently inside the step3 block at ~line 192) to the top of the escalation function and reuse it at both step2 and step3.

**Where to change:** `order_executor.py` → `fill_with_escalation()`, step2 block (~line 153). The intrinsic formula is already present in the step3 block (~lines 192–201) — hoist it above step2 and apply the floor there.

---

### Consider market-order fallback when bid < intrinsic at step3 (MISS exits)

**Problem:** When no buyer will pay intrinsic value at step3 — i.e. `bid < intrinsic` — the step3 limit order is placed at the intrinsic floor and goes unfilled. With no further fallback, the position MISSes and cap_pnl is recorded as $0 (incorrect). The engine has no mechanism to exit the position.

On 2026-04-17, this happened to 2 exits:
- **COIN P220 BRE A1**: step3 floored at $12.61; bid=$11.60 → MISS. cap_pnl=$0 (should be a real loss).
- **FN C620 A1**: step3 floored at $72.80; bid=$70.80 → MISS. cap_pnl=$0 (should be a real loss).

In both cases the bid was $1–$2 below intrinsic — market makers were not pricing in exercise value for same-day expiry options with tight liquidity near EOD.

**Design options (tradeoffs):**
1. **Market-order fallback after step3 MISS**: place a market SELL as absolute last resort. Guarantees exit but may fill far below intrinsic ($2–$5 slippage possible in illiquid markets).
2. **Floor step3 at bid instead of intrinsic**: always fills but abandons the intrinsic protection. Equivalent to option 1 in liquid markets; worse in illiquid ones.
3. **Alert only, no auto-exit**: log `MISS`, send SMS/Telegram, require manual close in TradeStation. Current behavior — but cap_pnl=$0 is misleading.

**Recommended next step:** At minimum, fix cap_pnl accounting for MISS exits (record the last known option mid as the estimated exit price rather than $0). The market-order fallback is a separate risk decision.

**Where to change:** `order_executor.py` → after the FILL_ESC MISS log (~line 219), return a sentinel value or raise a specific exception that `position_monitor.py` / `trade_engine.py` can catch to trigger a market-order exit attempt.
